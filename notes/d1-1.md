## Why this matters

Every value in Python has a type, and the type decides what you can do with it. Most beginner errors in coding tests come from mixing types, such as adding text to a number. Output-prediction MCQs in TCS and Infosys tests also ask about types and conversions directly.

## Core concepts

### The basic types

| Type | What it stores | Example |
| --- | --- | --- |
| int | Whole numbers of any size | 42, -7, 10**20 |
| float | Decimal numbers | 3.14, 6.5, 1e-3 |
| str | Text in quotes | "EIE", 'Python' |
| bool | True or False | True |
| NoneType | No value | None |
| complex | Complex numbers | 3 + 4j |

Use type() to check a value's type.

```python
print(type(42))      # <class 'int'>
print(type(6.5))     # <class 'float'>
print(type("6.5"))   # <class 'str'>
print(type(True))    # <class 'bool'>
```

### Implicit conversion

Python converts automatically only when it is safe, such as int to float in maths.

```python
x = 5 + 2.5     # 7.5, the int becomes a float
y = True + 3    # 4, because True counts as 1
```

### Explicit conversion

You convert yourself with these functions.

| Function | Converts to | Example | Result |
| --- | --- | --- | --- |
| int() | Whole number | int("25"), int(9.99) | 25, 9 |
| float() | Decimal | float("6.5"), float(3) | 6.5, 3.0 |
| str() | Text | str(100) | "100" |
| bool() | True or False | bool(0), bool("hi") | False, True |

Important details:

- int() on a float **cuts off** the decimal part. It does not round. int(9.99) is 9 and int(-2.7) is -2.
- int("6.5") gives an error. Use int(float("6.5")) instead.
- bool() is False only for "empty" values: 0, 0.0, "", None and empty collections. Everything else is True, even "False" as text.

### Floats are approximate

```python
print(0.1 + 0.2)          # 0.30000000000000004
print(round(0.1 + 0.2, 2)) # 0.3
```

Computers store decimals in binary, so some values are slightly off. Round when you display money or marks.

### Strings and numbers do not mix

```python
marks = 85
# print("Marks: " + marks)    # TypeError
print("Marks: " + str(marks))  # works
print(f"Marks: {marks}")       # best
```

## Worked examples

### Example 1: Predict the output

```python
a = "5"
b = 2
print(a * b)        # 55, because a string repeats
print(int(a) * b)   # 10
```

### Example 2: Read a decimal and round

```python
price = float(input("Price: "))   # user types 199.999
print(round(price, 2))            # 200.0
print(int(price))                 # 199
```

### Example 3: Truthy and falsy

```python
for value in [0, 1, "", "0", None, [], [0]]:
    print(repr(value), bool(value))
```

Output: 0 False, 1 True, '' False, '0' True, None False, [] False, [0] True.

## Common mistakes

- Expecting int(9.99) to give 10. It gives 9.
- Calling int() on text with a decimal point, such as int("6.5").
- Joining text and numbers with + without str().
- Comparing floats with ==, such as 0.1 + 0.2 == 0.3, which is False.
- Assuming bool("False") is False. Any non-empty string is True.

## Interview and test questions

**What is the output of type(10 / 5)?**
float, because / always returns a float. The value is 2.0.

**What does int(-3.8) return?**
-3, because int() truncates towards zero.

**What is "3" * 3?**
"333".

**Is Python strongly typed?**
Yes. It is dynamically typed, but it will not silently mix unrelated types such as str and int.

**What is the difference between None and 0?**
None means no value at all. 0 is a number. Both are falsy.

## Quick recap

- The main types are int, float, str, bool and None, and type() tells you which one you have.
- Python converts int to float automatically, but never str to a number.
- int() truncates, and round() rounds.
- Empty and zero values are falsy, and everything else is truthy.
- Floats are approximate, so round them for display.
